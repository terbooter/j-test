# Тестовое задание 
## О проекте

Это бэкенд-сервис на Fastify и TypeScript, предназначенный для управления иерархической структурой контентных блоков. Проект использует PostgreSQL в качестве базы данных с Drizzle ORM и Awilix для внедрения зависимостей.

## Задача

Ваша задача — доработать и улучшить существующий функционал сервиса. Ниже представлен список задач, которые необходимо выполнить.

### 1. Запуск и отладка проекта

Первым шагом необходимо полностью запустить проект на локальной машине и убедиться в его работоспособности.

**Проверьте все существующие эндпоинты** (например, через Postman или встроенную документацию Swagger/Scalar). Если вы обнаружите ошибки в их работе, исправьте их.

### 2. Обновление счетчика дочерних блоков

В схеме данных блока есть поле `childs`, которое должно отражать количество дочерних элементов. Сейчас это поле не обновляется автоматически.
Реализуйте логику, обновления `childs` у родительского блока. 

### 3. Добавление системы пользователей

В текущей реализации отсутствует разделение доступа по пользователям. Необходимо добавить базовую систему пользователей.
 Можно обойтись без эндпоинтов регистрации, добавив двух пользователей в систему хардкодом.
Все блоки, которые уже есть в базе данных, должны быть добавлены пользователю с условным именем `admin`.


### 4. Написание CI/CD для деплоя

Подготовьте проект к автоматическому развертыванию на удаленном сервере (VPS).
Напишите конфигурационный файл `.gitlab-ci.yml` для GitLab CI.


### 5. Проектирование хранения файлов

В контенте блоков (например, типа `article` или `idea`) есть поле `image`, которое сейчас предполагает хранение URL в виде строки. Это негибкое решение.

Продумайте и опишите, как можно реализовать систему загрузки и хранения файлов (изображений, документов и т.д.) для блоков.

*Реализовывать этот функционал кодом не требуется, достаточно детального текстового описания в отдельном файле `FILE_STORAGE.md`.*


Удачи!
